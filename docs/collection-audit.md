## 0.1.7 从文献到业务知识

原始需求的交付物是在 4.23 知识管理中可查看的一条新增或更新记录，能够追溯采集出处、人工审核和原件。重新读取原型的 `collection-redesign.js`、`collection-journey.js` 与 `collection-product-workspace.js`，可见原文核验、解析、知识审核、待同步和目标记录回执各有独立步骤。4.23 的类别、模板和字典是采集系统的输入，业务文献导入是可选来源。正式写入始终从「审核与同步」办理。

| 原问题 | 4.23 契约与修正 |
| --- | --- |
| 审核后的稿件在首页没有待同步入口，已处理数混入跳过记录 | 首页列出待同步、同步异常和相同已跳过。实际写入数与写入记录列表使用相同的口径。列表区分新增、更新和跳过，可打开对应业务知识 |
| 同篇论文可以支持多种知识，旧版以论文本身的 DOI 或原文标题匹配所有类型 | 期刊、书籍、指南按文献身份匹配。结构化知识按类型、子类型、所选子类和知识标题匹配。审核人可以按业务名称选定翻译名或别名不同的同类目标，差异预览保留业务标题。文献记录存在两个不同 DOI 时拒绝人工合并 |
| 更新只提交变化的字典项，检验检查更新没有携带原子类型 | `KnowledgeServiceImpl.save` 在保存时按类型重建关系。对空字典集合会删除原关系，类型 8 的保存分支还读取 `childType`。现在首次更新和补存附件引用都携带原子类型、类别和完整的预期字典关联，更新后逐组回读 |
| 出版社可能给不同 PDF 同名，业务端按目录和文件名存储 | 原生 `UploadService.saveFile` 将同名旧文件移到备份路径，再把新文件写入旧路径。采集系统现在用稿件 ID 和 SHA-256 生成存储名，绑定时保留原文件名。绑定前核对下载的字节，回读时检查对应记录的有效附件 |
| 旧版新增只确认同步标识和类型 | 新增完成前回读业务标题、类型及子类、已审摘要、模板值、所选字典与 PDF。回执可再次核对当前业务记录，缺失、回读失败与内容不一致都能体现。实际版本快照写入采集系统 |

### 仍有差异的操作

- 单次可设置 1 至 100 条，支持原型常用的 50 条。全网搜索按候选网址去重，超过 20 条时继续读取 SearXNG 后续页，最多读取十页。上传仍为每批 20 个文件，每份 20 MB。原型还提供不限数量。
- 原文资料类型和知识类别可在入库后核对、批量分配和筛选。原型的按资料内容类型预筛、部分站点的专用栏目规则和机构账号接入，仍需分别适配来源。
- 对照阅读使用服务器上的原始 PDF 或其他文件的提取文本。可按页跳转、缩放或打开完整 PDF。页图从服务器原件按需生成，仅在请求期间使用。段落级证据定位尚未实现。
- 业务结构使用 4.23 返回的字段和字典映射。采集端维护本地生成规则。原型允许直接新增、删除和重排业务字段，这部分仍由业务系统维护。

### 当时的执行规则与现场条件

- 0.1.3 验收时单次采集结果上限为 20，文件上限为每份 20 MB。原型展示了 50 条、自定义和不限量。栏目采集从指定页面提取站内链接。检索候选通过结果 ID 选取，采集使用搜索时记录的地址，并通过执行记录回溯原搜索。
- 全网检索使用 `MEDCOLLECT_SEARX_URL` 对应的 SearXNG JSON 接口。生产验收验证了搜索生成 20 条候选、选一条取得公开期刊全文和下载回读。Europe PMC 医学检索使用独立的 API。[验收交接](handoff.md#节点-12--searxng-部署与现网选采)
- 来源授权状态登记在采集系统。需要登录、机构代理或其他站点授权的来源，须配套可用的授权接入。原型的账号提交也依赖独立的来源授权服务。
- 知识生成模板的 4.23 字段 ID 和结构用真实业务模板。采集侧的规则在本应用保存，业务模板参数由 4.23 的维护流程生效。模型预审核结果供人工核对，正式同步以人工审核决定为准。
- 原型的按内容类型预筛和特定站点栏目规则依赖来源提供的标签或站点适配。此次验收覆盖已知文件格式、可读网页、来源记录区分及入库后的分类管理。
